# سرور اختصاصی میلانو — از «کانفیگ عمومی» تا نودِ مالِ خودتان

## چرا این پوشه وجود دارد (حقیقتِ مهم)

هیچ اپی — از جمله همین اپ — نمی‌تواند «سرور حرفه‌ای» را با کد خلق کند. سرور، یک ماشین واقعی
است که باید کسی پولش را بدهد و روشن نگهش دارد. لیست‌های عمومی رایگانی که اپ تا امروز از آن‌ها
تغذیه می‌کند سقف کیفیت مشخصی دارند: هزاران نفر هم‌زمان از یک UUID استفاده می‌کنند، IPها به‌سرعت
وارد لیست سیاه اپراتورها می‌شوند و نیمی از ردیف‌ها هر هفته می‌میرند. دقیقاً به همین دلیل روی
ایرانسل «گاهی» وصل می‌شد.

راه‌حل حرفه‌ای واقعی این است: چند VPS کوچکِ ارزان (هرکدام ۲ تا ۶ دلار در ماه) در چند کشور و ASN
مختلف، که روی هرکدام اسکریپت همین پوشه یک نود استاندارد بالا می‌آورد. URI خروجی را می‌گذارید در
لیست VIP اپ یا فایل `vip_raw.txt` بک‌اند؛ از آن لحظه کاربران‌تان به سرورِ خودتان وصل می‌شوند، نه
به استخر عمومی. **چند نود کوچک همیشه از یک نود بزرگ بهتر است**، چون واحدِ مسدودشدن IP است:
وقتی یک IP سوخت، بقیه زنده‌اند و شما فقط همان یکی را عوض می‌کنید.

## انتخاب VPS

| معیار | پیشنهاد |
|---|---|
| لوکیشن (به‌ترتیب) | ترکیه (استانبول) ← امارات ← ارمنستان/آذربایجان ← آلمان/هلند/فنلاند ← فرانسه |
| چرا | از ایران: همسایه‌ها ۴۰–۹۰ms، اروپای غربی ۹۰–۱۴۰ms، آمریکا ۱۸۰ms+. رتبه‌بندی داخل اپ (NodeRanking) همین ترتیب را می‌شناسد |
| منابع | ۱ vCPU و ۱GB RAM و ترافیک ≥۱TB برای شروع کافی است؛ Xray سبک است |
| سیستم‌عامل | Ubuntu 22.04/24.04 یا Debian 12 |
| تنوع | حداقل ۳ نود در ۳ دیتاسنتر/ASN متفاوت؛ هرگز همهٔ تخم‌مرغ‌ها روی یک رنج IP نباشد |

## نصب (یک دستور)

روی VPS تازه، به‌عنوان root:

```bash
curl -fsSL https://raw.githubusercontent.com/Companymeelano/VPN/main/server/install-meelano-node.sh -o m.sh
bash m.sh
```

اسکریپت چه می‌کند (و چه نمی‌کند):

- Xray-core رسمی را با نصب‌کنندهٔ رسمی XTLS نصب می‌کند.
- یک اینباوند **VLESS + Reality + Vision روی 443** می‌سازد (بدون نیاز به دامنه/گواهی؛ handshake
  شبیه بازدیدِ `www.microsoft.com` است — با `SNI=... DEST=...` می‌توانید سایت پوششی را عوض کنید).
- به‌صورت اختیاری با `DOMAIN=cdn.example.com bash m.sh` یک مسیر دوم **WS+TLS** پشت Caddy (با گواهی
  خودکار) روی 443 می‌گذارد و Reality را به 8443 می‌برد. دامنه باید قبلش با رکورد A به همین VPS
  اشاره کند.
- `BBR` را روشن و فایروال `ufw` را می‌بندد (فقط SSH + پورت‌های لازم باز می‌مانند).
- لاگ مسیر کاربران را ذخیره نمی‌کند (`loglevel: warning` و بدون access log مقصدها).
- خروجی: یک یا دو URI آماده، هم چاپ می‌شود هم در `/root/meelano-node.txt` می‌نشیند.
- اجرای دوباره بی‌خطر است: هویت (UUID/کلید Reality) حفظ می‌شود تا لینک‌هایی که قبلاً پخش کرده‌اید
  نشکنند. برای چرخاندن هویت: `ROTATE=1 bash m.sh` — توجه: چرخاندن هویت، **IP سوخته را درمان
  نمی‌کند**؛ درمانش فقط IP یا VPS تازه است.

## وصل‌کردن نود به اپ

دو راه دارید؛ دومی برای همهٔ کاربرها اعمال می‌شود:

1. **تستی/شخصی:** URI را در اپ، بخش VIP، الصاق کنید.
2. **رسمی:** URIها را (هرکدام یک خط) در هاست، فایل `public_html/v/data/vip_raw.txt` بگذارید یا از
   پنل ادمین (`/v/admin/` ← VIP list) اضافه کنید. بک‌اند خودش تست، رتبه‌بندی ایران‌محور و ماسک
   برند انجام می‌دهد و در فید VIP پخش می‌کند.

## نگه‌داری ماهانهٔ حداقلی

- `systemctl status xray` و یک تست اتصال از سیم‌کارت ایرانسل + همراه‌اول.
- آپدیت: اجرای دوبارهٔ همان اسکریپت (نصب‌کنندهٔ Xray خودش آخرین نسخه را می‌آورد؛ هویت حفظ می‌شود).
- اگر نودی از داخل ایران مرد ولی از خارج زنده بود → IP آن نود سوخته؛ جایگزینش کنید، دنبال باگ
  در اپ نگردید.
- امنیت SSH: کلید به‌جای پسورد، و پسورد root قوی. ترافیک کاربران از این ماشین رد می‌شود؛ با آن
  مثل یک دارایی حساس رفتار کنید.

## چیزی که هیچ سروری درستش نمی‌کند

در شب‌های قطعی سراسری (وایت‌لیست شدن اینترنت ملی) هیچ نود و هیچ اپی وصل نمی‌شود؛ این محدودیت
فیزیکی است، نه باگ. هدف واقع‌بینانهٔ این معماری: در شرایط «معمولیِ سخت» ایران، اتصال پایدار و
سریع برای اکثر کاربرها در اکثر ساعت‌ها، با فیل‌اور خودکار بین چند نود.
