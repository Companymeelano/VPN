# AI روی سرور — تقسیم کار، و مرزهایش

## ۰. یک جمله‌ای که همه‌چیز از آن می‌آید

**مدل هیچ‌وقت در مسیر اتصال نیست.** هر چه AI تولید می‌کند در *ساختنِ فید* نوشته می‌شود و اگر نبود،
فید همان شکلِ قبلی را با همان قاعده‌های قطعی می‌گرفت. پس «هوا/API قطع است» هرگز به کاربر به‌صورت
«اینترنت نداری» برنمی‌گردد.

## ۱. تقسیم کار (هر تسک: ورودی، خروجی، مدل، جایگزینِ بی‌AI)

| تسک | ورودی | خروجی (در قرارداد) | مدل پیش‌فرض | اگر AI نبود |
|---|---|---|---|---|
| `tune` | فکت‌های ۴۰ گره + آمارِ ناوگان (tcpFail/tlsFail/dnsPoisoned/rating) | `servers[].tune` (patch) | گرانِ ارزان (gpt‑4o‑mini / llama3.1) | `AiTune::heuristic()` — همان جدولِ docs/ANTI-BLOCK.md §۳ |
| `regime` | تجمیعِ بازخورد کاربرها + رأی‌های regime | `meta.regime`، ترجیح ترتیب | همان | آستانه‌های `regimeFromFleet()` (tcpFail/tlsFail/dns) |
| `rank` | فهرست نهایی + کیفیتِ سنجیده‌شده | ضریبِ ۰٫۸۵..۱٫۱۵ روی ترتیب | هرچه ارزان‌تر | بدون تغییر ترتیب (خاموش به‌صورت پیش‌فرض) |
| `advice` | `err` + regime + proto + tier | `{title,body,action}` فارسی برای کاربر | مدلِ *بهتر* (متن، نه عدد) | جدولِ ازپیش‌نوشته‌ی `cannedAdvice()` |
| پشتیبانی (ادمین) | لاگِ build/فیدبک | خلاصه و پیشنهاد برای ادمین | اختیاری | لاگ خام |

## ۲. چرا این تقسیم، نه «یک مدل برای همه‌چیز»

1. **tune/regime کارِ عددی است، نه زبانی.** مدل برای *مقایسه‌ی هم‌زمان* چهل گره استفاده می‌شود — همان‌جا
   که قاعده‌ی انسان‌نویس ضعیف است («این چهار تا میزبانِ یکسان روی پورت‌های متفاوت‌اند»)، و برای بقیه
   چرخه به همان قاعده‌ی قطعی واگذار می‌شود. هزینه: یک فراخوانی برای کل ناوگان، در هر build، کش‌شده.
2. **advice کارِ زبانی است.** متنِ فارسیِ مناسبِ «اتصال برقرار نشد» با template بی‌کیفیت می‌شود؛ پس آنجا
   مدلِ بهتر را هزینه می‌کنیم، ولی فقط وقتی کاربر واقعاً خطا دیده (نه در هر رفرش).
3. **rank خاموش است.** رتبه‌بندی را سنجه تعیین می‌کند، نه سلیقهٔ مدل. کلید `ai.tasks.rank.enabled=true`
   برای کسی است که می‌داند دارد چه کار می‌کند؛ سقفِ تأثیر هم ۱۵٪ است چون یک مدلِ بدروزه نباید
   فهرست را وارونه کند.

## ۳. نگهبان‌ها (هر کدام در کد، نه در آرزو)

- `Ai::clamp()` با `AiTune::patchSchema()`: فقط کلیدهای مجاز، اعداد در بازه، enumها از فهرست، کلید
  ناشناخته حذف، کاراکترهای کنترلی از متن حذف، رشته تا ۱۸۰ نویسه. بازه‌ها **همان بازه‌های
  `net/Regime.kt`** هستند؛ دو نگهبان، یک قرارداد.
- «گره‌ای که نفرستادیم را دست نمی‌زنیم»: `askModel()` خروجی را با `ids` ورودی تقاطع می‌گیرد؛ هر
  `id` ساختگی دور ریخته می‌شود.
- `why` (یادداشتِ مدل) به کلاینت نمی‌رود؛ فقط در لاگ ادمین می‌ماند.
- بودجه: `ai.dailyTokenCap` و `ai.dailyUsdCapCents` با شمارنده‌ی روزانه در `data/ai-spend.json`.
  سقفِ روز = ۴۰۰٬۰۰۰ توکن و ~۰٫۶۰ دلار؛ بعد از آن، روز تمام است و heuristic کار می‌کند.
- مدارِ محافظ: سه خطای پیاپی ⇒ ۱۰ دقیقه خواب (`data/ai-breaker.json`)؛ build روی timeout معلق نمی‌ماند.
- زمان: `ai.timeoutSeconds=8`، بدون redirect، سقف پاسخ ۲۵۶KB، `response_format=json_object`.
- کش به ازای هر تسک (`ai.cacheTtl`)، پس ۴۰۰ رفرشِ دقیقه‌ی یک فهرستِ کوچک، یک فراخوانی است نه چهارصد.

## ۴. حریم خصوصی: چه چیزی از کاربر بیرون می‌رود

فقط این‌ها، روی همان `?action=feedback`: شناسه‌ی گره، موفق/ناموفق، تأخیر، و بلوک `block`
(`tcpFail/tlsFail/rtt/probes/dnsPoisoned`) + `regime` محلی. **IP، مکان، نام کاربر، فهرست سایت‌ها و
ترافیک هرگز.** aggregate در `data/block.json` به‌صورت EWMA و شمارنده‌ی رأی نگه داشته می‌شود؛ یعنی
نمی‌توان از رویش «این کاربر فلان شبکه است» را فهمید. اگر `tune.minVotesForRegime` (پیش‌فرض ۳) تأمین
نشود، رأیِ جمعی اصلاً اعمال نمی‌شود — یک کاربرِ تنها نمی‌تواند ناوگان را تکان بدهد.

## ۵. فعال‌کردن روی هاست اشتراکی

`config.local.php`:

```php
<?php return [
  'ai' => [
    'enabled' => true,
    'default' => 'openai',
    'providers' => ['openai' => ['key' => 'sk-...', 'model' => 'gpt-4o-mini']],
    'tasks'   => ['advice' => ['model' => 'gpt-4o']],   // متنِ کاربر: مدلِ بهتر
  ],
];
```

هیچ cron لازم نیست: همه‌چیز داخل همان درخواستِ build اجرا می‌شود (و کش). اگر خواستید مدل روی سرورِ
خودتان باشد، provider `ollama` از پیش تعریف شده است — تنها حالتی که `http://` در آن مجاز است،
چون دامنه‌ی بلاک‌شدنِ API‌های خارجی در این منطقه یک سناریوی واقعی است، نه نکته‌ی حاشیه‌ای.

## ۶. تست

`backend/v/tests/run.php` پانزده ادعای این لایه را می‌زند، با `ai.enabled=false` (پیش‌فرض کارخانه):
regime از آستانه‌ها، درستیِ patch برای reality/grpc/HY2/پورت غیراستاندارد، clampها (عدد/enum/b bool/
رشته/کلید شیطانی)، نیامدنِ `why` در payload، و build کاملِ فید با tuner روشن. یعنی «AI نیست» هم
آزمون‌شده است، نه فقط فرض.
