# مقاومت در برابر انسداد — مدل تهدید، پارامترها، و چیزهایی که عمداً انجام نمی‌دهیم

این فایل «چرایی» عدد‌هاست. اگر کسی مقدار `fragSize` یا ترتیب ترابری را عوض کند، باید بداند کدام رفتار
شبکه را دارد عوض می‌کند — وگرنه تنظیم، حدس است.

## ۱. مدل تهدید (ایران، ۱۴۵)

| لایه | چه کار می‌کند | نشانه‌ی مشاهده | پادمان ما |
|---|---|---|---|
| DNS | مسموم‌کردن رکورد برای دامنه‌ی فید و دامنه‌های گره | جواب resolve‌شده با جواب DoH نمی‌خواند | `NetGuard.doh()` با dial روی IP ریزolver؛ اگر مسیر عادی شکست و مسیر پین‌شده موفق شد ⇒ `dnsPoisoned=true` |
| SNI | قطع بر اساس نامِ داخل ClientHello | TLS روی ۴۴ می‌میرد ولی TCP باز می‌شود | Reality / دامنه‌ی پوششی / `alpn` همرنگ مقصد |
| شکل TLS | تطبیق ترتیب پسوند‌ها و اندازه‌ی ilk record | همان اتصال با دو client مختلف، یک‌در‌میان قطع می‌شود | `fingerprint=chrome` + تکه‌تکه‌سازی handshake |
| تزریق RST | فرستادن RST جعلی بعد از چند بسته | ترافیک چند ثانیه می‌رود بعد می‌بندد | MTU/MSS پایین، fragment، اتصالِ بلند (reuse) به‌جای handshake جدید |
| خفگی UDP/QUIC | نرخِ UDP روی پورت‌های معمول | handshake موفق، داده نمی‌رود | کاهش MTU به ۱۲۰ و روی HY2/TUIC؛ در «سنگین» TCP اولویت می‌گیرد |
| انسداد پورت | دراپ کل پورت‌های غیر ۴۴۳ | ۸۰٪ گره‌ها جواب نمی‌دهند | نردبان سیاهه (regime=BLACKOUT) + تنزیل محلی، حذف نه |
| فینگرپرینت پروتکل | تشخیص «این WebSocket است» | اتصال پایدار ولی فقط در ساعات کم‌ترافیک | grpc multi-mode، xhttp، path/Host بی‌هویت |

## ۲. سه سطح regime (و چرا «خودکار»)

`CALM` = فقط SNI فیلتر است؛ `TIGHT` = RST + شکل‌شناسی TLS؛ `BLACKOUT` = پورت‌ها می‌mirند.
هر سطح **هزینه** دارد: تکه‌تکه‌سازی یعنی رفت‌وبرگشتِ بیشتر، mux یعنی سر‌به‌سر شدن روی لینک پرنویز، MTU
پایین یعنی سقفِ نرخ کمتر. پس پیش‌فرضِ همیشگیِ «سنگین‌ترین حالت ممکن» درست نیست؛ عددِ درست وابسته به
وضعیت امشب است. `AppSettings.regime = "auto"` یعنی رأیِ محلی (پراوب TCP/TLS روی ۱۲ گره‌ی اول)
تصمیم می‌گیرد و رأیِ تجمعیِ سرور (که از بازخورد همه‌ی کاربرها ساخته می‌شود) آن را override می‌کند.

پیش‌فرضِ کارخانه: **`tight`** — چون در شرایط فعلی ایران، حالتی که «کار نمی‌کند ولی سریع است» از
«کمی کندتر ولی وصل می‌شود» بدتر است.

## ۳. عدد‌ها و دلیلشان

| پارامتر | آرام | سنگین | قطعی | چرا |
|---|---|---|---|---|
| `mtu` | 1280 | 1280 | 1280 | ۱۴۰۰ روی تونل + سربارِ v6 به PMTUD blackhole می‌خورد؛ همان «وصل است ولی سایت باز نمی‌شود» |
| `mss` | 0 (دست نزن) | 1300 | 1240 | clamp کردن MSS ارزان‌تر از fragment کردنِ TCP است |
| `fragSize` | 0 | 200 | 120 | هدف: شکستن اندازه‌ی ilk record؛ از ~۱۰۰ کمتر فقط تأخیر می‌آورد |
| `fragCount` | 1 | 2 | 3 | تعداد برشِ handshake |
| `fragStrategy` | — | variable | random | `fixed` الگو می‌سازد؛ الگو همان چیزی است که DPI دنبال آن است |
| `fragDelayMs` | 0 | 20 | 40 | فاصله‌ی برش‌ها؛ بالا رفتنش مثلِ یک slow-loris بی‌خطر دیده می‌شود |
| `mux` | true | true | true | handshake کمتر؛ **روی grpc و Reality خاموش** (grpc خودش multiplex دارد، Reality با mux روی بعضی بیلدها قفل می‌کند) |
| `keepAliveSec` | 30 | 15 | 10 | NAT/flow-timeout اپراتور موبایل معمولاً ۳۰–۶۰ ثانیه است |
| `alpn` | h3,h2 | h3,h2 | h3,h2 | hello بی‌رنگ‌تر؛ روی ws: `h2,http/1.1` |
| `fingerprint` | chrome | chrome | chrome | uTLS؛ `random` خطرناک است چون بعضی مقصد‌ها ترتیبِ عجیب را رد می‌کنند |
| `allowLan` | false | false | false | false = ترافیک LAN bypass ⇒ پرینتر/کروم‌کست/NAS با VPN می‌میرند؛ این تصمیمِ محصول است، نه تنظیم فنی |

## ۴. ترتیبِ ترابری (نردبان)

`Ladder.order()`: در TIGHT اول `reality`، بعد `xhttp-tls`، بعد `grpc-tls`؛ در BLACKOUT اول
`reality/grpc-tls/xhttp` و **`tcp-plain` در ته**، چون handshake بازِ TCP اولین چیزی است که drop می‌شود.
این فقط **ترتیب** است، نه فیلتر: گره‌ای که در رتبه‌ی بدتری می‌نشیند حذف نمی‌شود. فهرستِ خالی بدترین
خروجیِ ممکنِ این محصول است.

## ۵. تنبیه محلی، نه حذف

`ServerFeedRepository.probeAndReconcile()` حداکثر ۱۲ گره‌ی اول فهرست را از خودِ گوشی پروب می‌کند
(TCP ۱٫۲ ثانیه؛ TLS با ALPN اگر TCP رد شد). نتیجه در `localPenalty()` به‌عنوان **معیارِ سومِ مرتب‌سازی**
ورود می‌کند: `pinned → penalty → slot`. اگر پروب جواب نداد، گره پایین می‌آید و برچسب
«از این مسیر پاسخ نداد» می‌گیرد؛ هرگز پاک نمی‌شود، چون مسیر می‌تواند نود ثانیه بعد برگردد و
کاربر نباید فهرستش را از دست بدهد.

## ۶. DNS: تنها راهِ قابل‌اتکا

`NetGuard.doh()` سه ریزolver را هم‌زمان می‌پرسد (Google 8.8.8.8، Cloudflare 1.1.1.1، AliDNS 223.5.5.5)
و **هر کدام را با IP خودش dial می‌کند؛ یعنی resolver محلی هیچ‌جای این مسیر نیست. جواب‌ها union
می‌شوند و به ترتیب «تعداد موافقت» رتبه می‌گیرند: یک sinkhole معمولاً فقط در یک پاسخ ظاهر می‌شود.
AliDNS عمداً در لیست است: چینی است، تاریخاً وقتی Google/Cloudflare throttle می‌شوند زنده می‌ماند،
و cache خشنی دارد که برای ما مزیت است.

پس از موفقیتِ مسیر پین‌شده، `lastDnsPoisoned=true` ثبت و با فیدبک به سرور فرستاده می‌شود؛ آنجا
`AiTune::regimeFromFleet()` همان را به‌تنهایی به regime=`tight` ترجمه می‌کند (مسمومیت DNS یعنی
«دارند دامنه را می‌گیرند»، حتی اگر تأخیر صفر باشد).

## ۷. پیش‌فرض‌های AppSettings برای ایران

`regime="tight"`، `killSwitch=true`، `secureDns=true`، `smartReconnect=true`، `autoSelect=true`،
`fragmentAuto=true`، `muxEnabled=true`، `realityFirst=true`، `autoConnectOnBoot=true`، `mtu=1280`،
`feedback=true` (بدون بازخورد، رتبه‌بندیِ سرور کور است)، `autoUpdate=true`.
همه روی `true`/مقدارِ محافظه‌کار شروع می‌شوند چون «اولین نصب» تعیین‌کننده‌ی قضاوت کاربر از محصول است.

## ۸. چیزهایی که عمداً انجام نمی‌دهیم

1. **توهم «ضدفیلتر بودن» نمی‌فروشیم.** هیچ‌کدام از این‌ها قول اتصال نمی‌دهد؛ حداکثر شانس را بالا می‌برد.
   اگر هسته‌ی تونل در بیلد وصل نباشد (`CORE_LINKED=false`)، UI همین را می‌گوید و `assembleRelease` رد می‌شود.
2. **پراوبِ انبوه نمی‌فرستیم.** ۱۲ هدف، ۱٫۲ ثانیه، کش چنددقیقه‌ای. یک کلاینت که هر ۳۰ ثانیه ۴۰۰ پورت
   را اسکن کند، خودش شبیه حمله است و دقیقاً همان چیزی است که IP کاربر را وارد لیست سیاه می‌کند.
3. **`allowInsecure` را روشن نمی‌کنیم** مگر آن‌که خود فید برای یک گره بگوید؛ و آن‌وقت هم در UI نوشته می‌شود.
4. **MTU را با آزمون‌وخطای کاربر تغییر نمی‌دهیم**؛ یک عدد از رنجِ مجاز، وگرنه «سریع‌ترین حالت = اتصالِ بدون ترافیک» را تجربه می‌کند.
5. **دخالت AI در اتصال لحظه‌ای صفر است.** هر چه AI می‌گوید در *ساخت فید* اعمال می‌شود (اسناد: docs/AI.md)،
   پس قطع‌شدن API هیچ‌وقت «قطع اینترنت» به کاربر نشان نمی‌دهد.
6. **قفل/سپر روی آیکن نداریم** — نه به‌خاطر سلیقه: نشان‌های امنیتی انتظارِ «امنیت» می‌سازند که
   یک VPN خانگی نمی‌تواند جواب بدهد (BRAND.md §۱).

## ۹. چطور دستی بسنجیم

```bash
# ۱) DNS محلی دروغ می‌گوید؟ (خروجی باید یکسان باشد)
dig +short ainetmee.ir                # از داخل شبکه‌ی مورد نظر
# ۲) پورت باز است یا TLS می‌میرد؟
timeout 3 bash -c '</dev/tcp/HOST/443' && echo tcp-ok || echo tcp-fail
openssl s_client -connect HOST:443 -servername SNI -alpn h2,http/1.1 </dev/null 2>&1 | grep -E "ALPN|verify|error"
# ۳) رفتارِ regime را روی دستگاه ببین: تنظیمات ▸ مقاومت  «آخرین سنجشِ مسیر»
adb shell dumpsys activity broadcasts history | grep -c meelano   # رویدادهای اتصال/بازگشت
```

## ۱۰. بازگشت

همه‌چیز در یک نقطه خاموش می‌شود: در `config.local.php` مقدار `tune.enabled = false` ⇒ فید دقیقاً به
شکلِ پیش‌از‌AI برمی‌گردد (بدون کلید `tune`)، و کلاینت هم با `regime="calm"` و `fragmentAuto=false`
به رفتار خام برمی‌گردد. هیچ رفتارِ جدیدی در لایه‌های پایین‌تر قایم نشده که با یک سوییچ برنگردد.
