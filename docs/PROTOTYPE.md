# پروتوتایپ زنده — `design/preview/`

یک فایل HTML مستقل، بدون build و بدون شبکه. هدف: تصمیم‌های `docs/DESIGN-SYSTEM.md` قبل از
کامپایل شدن **دیده و اندازه‌گیری شوند**، نه فرض.

```bash
python3 -m http.server 8099 --directory design/preview      # بعد http://localhost:8099/
```

## چه چیزی دارد
| بخش | چرا در پروتوتایپ است |
|---|---|
| قاب گوشی + کنترل اتصال | bezel/well/طوق، سه حالت + خطای واقعی، long-press روی سرورها |
| اسپارک‌لاین MB/s | نمونه‌برداری واقعی ۸Hz روی canvas؛ نشان می‌دهد اسپارک‌لاین در عرض ۲۰dp چند پیکسل است |
| شمارنده‌ی FPS | عدد واقعیِ frame‌های ۵ ثانیه‌ی اخیر؛ با `prefers-reduced-motion` مقایسه می‌شود |
| شبیه‌ساز فریز | **قبل** = notify طوفانی روی main → فریز ۲.۴ ثانیه؛ **بعد** = notify با دروازهٔ ۱Hz + کار در worker |
| فازهای اتصال | پروفایل ۱۵٪ → DNS ۳۰٪ → دست‌دادن ۵۰٪ → تونل ۷۰٪ → تأیید ۸۸٪ |
| لیست سرور | همان آناتومی ردیف برای Vip/free، سنجاق، چип‌های فیلتر، حالت تهی |
| آینه‌ی نوتیفیکیشن و کاشی QS | نشان می‌دهد بیرون از اپ چه چیزی از طراحی زنده می‌ماند |
| توکن‌ها/پالت/برند | کنتراست‌های واقعی (نه رزومه‌ای) + ماسک‌های لانچر + monochrome |

## قوانین
- **توکن‌ها CSS custom property هستند و در `Color.kt` هارد‌کد شده‌اند.** عدد را این‌جا عوض کنی،
  فردا در اندروید گم می‌شود؛ پس هر دو باید هم‌زمان ویرایش شوند (چک‌لیست release یادآوری می‌کند).
- اعداد تست با `tnum` رندر می‌شوند؛ اگر فونت عددی سیستم tabular نباشد، پروژه‌ی واقعی باید
  `fontFeatureSettings = "tnum"` را نگه دارد.
- هیچ انیمیشنی بالای ۴۰۰ms هنگام `connecting` نیست. اگر اضافه‌اش کردی، همان حس «فریز» برمی‌گردد.

## چطور با پروتوتایپ کار کنیم
1. تغییر را این‌جا بزن، با FPS‌متر و با ۲.۴ ثانیه‌ی فریزِ «قبل» مقایسه کن.
2. بعد عیناً به `VpnControlPanel.kt` / `HomeScreen.kt` منتقلش کن.
3. هر چیزی که این‌جا با `prefers-reduced-motion` بد به‌نظر برسد، در اپ هم بد است —
   `MotionPrefs.reduced` را فراموش نکن.

## کارت «کنترل‌ها» (از ۲٫۱)
چهار قاعده‌ی `ui/Controls.kt` با CSS بازتولید شده‌اند تا «give» و عمق را **قبل از بیلد اندروید** بشود قضاوت
کرد: دکمه‌یPrimary با هاله‌ی نفس‌کشنده (۲۴۰۰ms، دقیقاً `Motion.breath`)، Tonal با لبه‌ی مویی، Ghost که
فقط در فشار صورت می‌گیرد، Danger بی‌هاله، چیپ فعال (بلندتر، نه فقط سبزتر)، segmented با pill لغزنده روی
`cubic-bezier(.3,1.4,.5,1)` (همان فنرِ `MeelanoSegmented`)، و راکرِ سوییچ که سایه‌اش در فشار کوتاه می‌شود.
دِمو دو ادعایی را هم ثابت می‌کند که CSS تنها نمی‌تواند: pill جابه‌جا می‌شود (نه رنگ عوض می‌کند) و
**ردیف، هدفِ کلیک است** — کلیک روی متن تنظیمات هم سوییچ را عوض می‌کند.
`prefers-reduced-motion` نفس و چرخش‌ها را خاموش می‌کند، ولی حالت فشرده را نه: بازخوردِ لمس تزئینات نیست.
